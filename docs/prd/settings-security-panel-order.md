# 设置页：账号安全面板上移到运行诊断之前

UI-77（第 125 轮浏览器实测，第 128 轮交付）

## 问题

设置页「界面」标签页是一个单列滚动栈，顺序固定为：运行概览 → 投递暂停 → 运行时限 →
Worker 健康 → 存储 → 偏好 → 账号安全
（`apps/console/src/features/configuration/ui/settings-page.tsx:37-43`）。

「账号安全」面板里唯一的操作是「退出其他设备」——这是丢电脑、共享 Owner 密码、人员离场时的
应急动作，不是低频账号管理。但它排在整页最底部：1440×900 需要向下滚动约 528px，390×844 需要
滚动约 1942px 才能看到该按钮（第 125 轮浏览器实测，截图
`/tmp/tocsin-r125-ui/02-settings-1440-security.png`、`/tmp/tocsin-r125-ui/30-settings-390-top.png`）。
应急时刻的操作入口不应藏在只读诊断信息之后。

## 用户故事

作为值班工程师，我怀疑账号凭据泄露、需要立刻让其他设备下线时，打开设置页应当就能看到
「退出其他设备」，而不是先滚过运行时限、Worker 健康、存储用量等只读诊断。

## 范围

- 把 `SettingsSecurityPanel` 移到 `SettingsDeliveryPausePanel` 之后、`SettingsRuntimePanel`
  之前：应急操作与同为「可写操作」的投递暂停相邻，只读诊断整体后移。
- 更新 `settings-layout.ts` 中描述面板堆叠顺序的注释，保持与代码一致。
- 新增结构回归测试：断言「界面」标签页内账号安全面板在运行时限面板之前渲染，避免后续插入
  面板时又把应急入口挤回底部。

## 非目标

- 不改「账号安全」面板的内容、查询、撤销语义或 i18n 文案。
- 不改滚动容器策略（`settingsUiPanelClassName` 在所有断点自身滚动，第 124 轮已修）。
- 不拆分设置页为多个标签页，不改其它标签页。
- 不处理 UI-78/UI-79 等窄屏会话表问题。

## 验收标准

1. 1440×900 打开 `/settings` 的「界面」标签页，首屏即可看到「退出其他设备」按钮。
2. 390×844 下滚动距离显著缩短（相对当前 1942px），面板本身不横向溢出。
3. 面板顺序为：运行概览 → 投递暂停 → 账号安全 → 运行时限 → Worker 健康 → 存储 → 偏好。
4. 结构测试断言顺序；`vp check`、`vp run -r test`、`vp run -r build` 全绿。

## 架构边界

- 只改 `features/configuration/ui` 的页面组合与注释，不新增依赖、不改 schema、不改 oRPC 契约、
  不改投递/路由/auth 语义。
- 面板组件自身不感知顺序；排序由页面拥有，符合「组件单一职责」。
