# 一次性接入 Token 提示条的操作安全

## 状态

已实现（第 106 轮）。

## 问题

告警源创建或轮换 Token 后，页头会出现一次性提示条，这是运维**唯一**能拿到明文
接入 Token 的时机。当前提示条把不可恢复的「复制 Token」放在次按钮（`outline`）
上，却把可随时重新获取的「复制 URL」放成主按钮；右上角还有一个无确认的关闭图标，
误点一次就会永久丢弃 Token，页面上也没有任何补救入口。

证据：`apps/console/src/features/sources/ui/source-token-notice-panel.tsx:54-72`
（Token 为 `variant="outline"`、URL 为默认主按钮）、同文件 `:74-84`（关闭图标直接
调用 `onDismiss`）。提示条同时用于创建（`sources-page.tsx:74`）与轮换
（`sources-page.tsx:113-125`）。

## 用户故事

作为值班 SRE，我创建或轮换告警源后，希望最显眼的动作是「复制 Token」，并且关闭
提示条只能通过明确的「我已保存」完成；这样我不会因为点到角落的叉号而永久丢失
一个刚生成、无法再次查看的 Token。

## 范围

- 把「复制 Token」改为默认（主）按钮，「复制 URL」改为 `outline` 次按钮。
- 移除右上角无确认的关闭图标；提示条只保留底部显式的「我已保存」作为关闭动作。
- 删除因此不再使用的 `sources.notice.dismiss` 中英文案（保持两侧 key 对等）。
- 组件测试：Token 复制按钮为主按钮、URL 复制按钮为次按钮；关闭只能通过
  「我已保存」触发，且页面上不再存在「关闭提示」按钮。

## 非目标

- 不改变 Token 的生成、返回、存储或展示时机；仍不写入查询缓存、URL、浏览器存储
  或日志。
- 不新增确认对话框、不在关闭时拦截导航、不做「稍后再说」。
- 不改告警源创建/轮换表单与其它页面。

## 验收标准

- 「复制 Token」使用默认按钮样式（主操作），「复制 URL」使用 `outline`（次操作）。
- 提示条 DOM 中不存在「Dismiss notice」/「关闭提示」按钮；点击「I saved it」/
  「我已保存」触发一次 `onDismiss`。
- 复制成功/失败的 toast 行为与改动前一致。
- `vp check`、`vp run -r test`、`vp run -r build` 通过。

## 架构边界

- 纯前端组件与文案改动：无 oRPC 契约、无 DTO、无数据库、无迁移、无投递/路由/鉴权
  语义变更。
- 一次性 Token 仍只存在于该组件的瞬时 props 中，符合 AGENTS.md 的 token 例外条款。
