# 补投预览：目标级明细与执行范围一致

## 问题

补投（replay）是值班者在「告警已经恢复、但当时路由没命中或目标刚建好」时补发通知的最后手段。
预览对话框是确认动作前的唯一依据，但两处预览都没有把「到底会创建哪些投递」说清楚：

- 事件补投预览：服务端已经返回目标级明细 `EventReplayPreview.targets`
  （路由、通知目标、是否会新建、已存在时的投递 id），
  但对话框只渲染三个计数徽标，`targets` 从未被消费
  （`apps/console/src/features/events/ui/event-replay-action.tsx:155-178`）。
  值班者看到「可新建 3 条投递」，却不知道这 3 条分别发往哪条路由的哪个通知目标。
- 路由补投预览：候选列表只渲染前 10 条
  （`apps/console/src/features/routes/ui/route-replay-prompt.tsx:164` 的
  `preview.candidates.slice(0, 10)`），而确认时提交的是**全部**候选事件 id
  （同文件 `:42,54-57`，服务端上限 100）。预览数量与执行数量不一致，
  第 11 条之后的候选在确认前完全不可见。

影响：补投是会产生真实外发通知的破坏性操作。预览不完整时，值班者要么凭猜测确认，
要么放弃补投去手工逐条处理，都会拉长故障恢复时间。事件补投场景还可能出现
「同一条路由下两个目标，其中一个已有投递」这种必须逐目标判断的情况，计数徽标无法表达。

## 用户故事

作为值班工程师，当我准备补投一个历史事件时，我希望在确认对话框里看到每条命中路由下
每个通知目标是「将新建」还是「已存在」，以便确认这次补投不会重复打扰已经收到告警的人。

作为值班工程师，当我准备为一条路由批量补投最近事件时，我希望对话框列出的候选数量与
确认后实际执行的数量一致，以便在点击确认前完整评估影响面。

## 范围

- 事件补投预览对话框：在计数徽标下方新增目标明细列表，逐行展示
  「新建 / 已存在」徽标、路由名与通知目标名；容器沿用现有 `max-h-56` 滚动样式。
- 通知目标名来自现有的 `destinationsQueryOptions()` 列表查询（与同页
  「按事件创建静默」对话框一致的按需加载方式），按 `destinationId` 映射；
  目标已删除或列表尚未返回时回退展示 id，不阻塞对话框。
- 路由补投预览对话框：移除 `slice(0, 10)`，渲染全部候选（容器已可滚动）；
  每个候选行新增「新建目标」徽标组，列出本次会新建投递的通知目标名。
- 新增中英文 i18n 文案（`events.replay.*`、`routing.replay.*`）。
- 新增两个组件的测试：目标明细渲染、已有/新建区分、候选不再截断。

## 非目标

- 不新增 oRPC 过程、不新增 DTO 字段：`EventReplayPreview.targets` 与
  `RouteReplayCandidate.targets` 已包含 `routeName` / `destinationId` / `alreadyExists`。
- 不改补投的匹配语义、去重语义、服务端上限或 worker 行为。
- 不改变预览查询的 `limit`（默认 20，服务端上限 100）。
- 不做分页、虚拟滚动或按目标筛选。
- 不为预览新增 SSR 预取：目标名按需加载，失败时回退 id。

## 验收标准

1. 事件补投预览在存在目标时渲染与 `targets` 等长的明细行，每行包含路由名、
   通知目标名与「新建 / 已存在」状态；`targets` 为空时不渲染列表。
2. 通知目标名能通过 `destinationsQueryOptions()` 解析；未命中时回退显示 `destinationId`。
3. 路由补投预览渲染全部 `candidates`，不再只显示前 10 条；
   候选行展示本次会新建投递的通知目标名。
4. 对话框原有标题、描述、暂停提示、确认/取消按钮与确认后行为不变。
5. 新增组件测试覆盖：目标明细行数与状态、目标名解析与回退、候选全部渲染。
6. `vp check`、`vp run -r test`、`vp run -r build` 通过；浏览器实测 1280 与 390 视口无横向溢出。

## 架构边界

- 纯前端切片：只改 `features/events/ui`、`features/routes/ui` 与 i18n 文案。
- 复用现有 `destinationsQueryOptions()` 与 TanStack Query 缓存，不新增 server-only 导入。
- 不碰 schema、迁移、secret、投递/路由语义；可整体回滚为删除该分支。
