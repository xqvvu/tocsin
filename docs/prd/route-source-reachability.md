# 路由的告警源可达性提示

## 问题

路由列表只展示路由自身的启停状态。当一条路由匹配的告警源全部被停用时，该路由仍然显示为「启用」，
但已经不会收到任何新告警。值班同学在排障时往往先怀疑解析器、投递目标或 worker，最后才发现是上游
告警源被关掉了——列表没有把这个事实放在同一行。

证据：`apps/console/src/features/routes/ui/routes-section.tsx` 的规则单元格只渲染规则分组与状态范围；
`packages/core/src/source/source.ts` 的 `SourceSummarySchema` 已带 `enabled`，且 Routes 页已经加载
`sources`（`apps/console/src/routes/_dashboard.routes.tsx`），不需要新增查询或 DTO。

## 用户故事

作为值班工程师，我在路由列表里看到一条「启用」的路由时，希望同一行能告诉我它的告警源是否已经被
全部停用，从而判断「没有告警」是上游安静还是路由根本收不到事件。

## 范围

- 在路由列表的「规则」单元格增加一个警示徽标：
  - 匹配的告警源全部停用 → 「告警源已停用」，提示中包含匹配数量；
  - 没有任何匹配的告警源（全量规则但系统内没有告警源，或引用的告警源已不存在）→ 「无告警源」。
- 仅当路由自身处于启用状态时展示；停用路由的「状态」列已经说明了问题。
- 纯前端派生计算，不改 oRPC 契约、不改数据库、不改路由匹配语义。

## 非目标

- 不改变路由匹配或投递行为，不阻止保存、不自动停用路由。
- 不计算部分停用（仍有至少一个启用源时保持可达，逐源覆盖已由 Sources 页的覆盖率列负责）。
- 不在通知目标覆盖率（REQ-138）或断流预警（NEW-R）中复用；它们各自独立立项。

## 验收标准

- 全量规则 + 所有告警源停用 → 显示「告警源已停用」，提示含源数量。
- 全量规则 + 至少一个告警源启用 → 不显示徽标。
- 显式 `sourceIds`：只按被引用的源判断；其中任一启用即可达。
- 被引用的源全部不存在，或系统内没有告警源 → 显示「无告警源」。
- 路由自身停用时无论源状态如何都不显示该徽标（状态列已表达）。
- 中英文案键保持同步；中文使用「告警源」术语。

## 架构边界

- 派生逻辑放在 `apps/console/src/features/routes/model/route-source-reachability.ts`，纯函数、可单测。
- 徽标为 `apps/console/src/features/routes/ui/route-source-reachability-badge.tsx` 的独立组件，
  文案经 `useTranslations()` 与 `routing.table.sourceReachability.*` 键获得。
- 不新增服务端依赖、查询或持久化字段。
