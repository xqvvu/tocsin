# 可移植配置：从文件载入

状态：已实现（REQ-186，2026-10-21）。

## 问题

备份恢复文档要求运维从导出的文件重新导入配置，但设置页只能粘贴文本：
`PortableConfigForm` 只有「导出当前配置」和「应用导入」两个动作，全仓不存在
`type="file"` 或文件读取路径。运维需要先找到备份文件、用编辑器打开、全选复制，
再粘贴进 CodeMirror，长 TOML 容易截断或混入多余内容，且无法确认粘贴的是否是
目标文件。

## 用户故事

作为值班 SRE，我希望在可移植配置页直接选择备份文件并载入编辑器，以便在恢复
配置时不依赖手工复制粘贴，同时仍然显式确认后才真正应用变更。

## 范围

- `PortableConfigForm` 页脚新增「从文件载入」按钮与隐藏的文件选择器，接受
  `.toml` / `.json` / `text/plain`。
- 选中文件后读取文本并填入当前格式的编辑器草稿，**不自动导入**；用户仍需点击
  「应用导入」并在确认气泡中确认。
- 读取前做两道本地校验：文件超过 1 MiB 或内容为空白时给出错误提示，保持草稿不变。
- 文件读取封装在 `#/lib/browser` 的 `readTextFile`（`createClientOnlyFn`），与
  `downloadTextFile` 同一边界。
- 中英文案：`configuration.portableConfig.loadFile`、`loadFileHint`、`fileEmpty`、
  `fileTooLarge`。

## 非目标

- 不新增导入接口、不改变导入校验/事务语义。
- 不自动推断文件格式，不跨格式填充（TOML 页只填 TOML 草稿）。
- 不保存最近使用的文件路径，不监听文件变化。
- 不做文件内容预览或差异对比（导入确认仍只看编辑器内容）。

## 验收标准

- 在 TOML/JSON 页选择文件后，编辑器内容变为文件文本，且未调用导入接口。
- 文件超过 1 MiB 时提示「配置文件超过 1 MiB」，不读取、不修改草稿。
- 文件内容为空白时提示「所选文件内容为空」，不修改草稿。
- 载入后「应用导入」按钮可用性仍由草稿是否非空决定。
- 再次选择同一个文件仍会触发载入（选择器值在每次变更后被重置）。
- 中英文案 key 对齐；组件与 hook 各有回归测试。

## 架构边界

- 纯前端切片：不触碰 schema、迁移、oRPC 契约、投递/路由/auth 语义。
- 文件 API 只在使用时调用，模块不引入新的服务端依赖。
- 不新增运行时依赖。
