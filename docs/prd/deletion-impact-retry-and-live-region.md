# 删除影响面：失败可就地重试、加载态可被读屏播报

UI-70 / UI-71（第 120 轮）

## 问题

删除告警源、路由或通知目标前，控制台会先读取「本次删除将级联销毁多少历史记录」。这个预览
请求在一次读失败后没有恢复路径：对话框里只剩一条告警，操作者要么关掉对话框重新打开，要么
在没有影响面信息的情况下直接删除。删除是不可逆操作，让操作者为了重试一次读请求而重开对话框
没有必要。

同时，加载态只有三行骨架屏和一段 `sr-only` 文本
（`apps/console/src/components/common/deletion-impact-notice.tsx:38-46`）。`sr-only` 文本位于
普通 `div` 内，不在任何 live region，读屏不会播报「正在统计」；明眼操作者也只能看到没有语义
的空骨架。

## 用户故事

作为值班工程师，我在删除一个有历史的告警源时，如果影响面计数读取失败，我希望能在对话框里
直接重试，而不是关掉重开；如果我使用读屏，我希望在等待统计时有明确播报，而不是面对一片空白。

## 范围

- `DeletionImpactNotice` 新增可选 `onRetry`：失败态在告警右上角渲染「重试」按钮
  （复用 `common.actions.tryAgain`），未提供时不渲染任何操作。
- 告警源、路由、通知目标三个删除对话框分别把 `onRetry` 接到
  `historyImpact.request(<id>)`，复用已有的请求状态机（清空旧的确认勾选、丢弃过期响应）。
- 加载态改为 `role="status"` 的可视 live region，文案从 `sr-only` 移到可见文本。
- 失败态继续保留 `Alert` 自带 `role="alert"`；失败是警告不是锁，删除按钮语义不变。
- 新增组件测试覆盖：加载态的可视文案在 live region 内；失败态提供重试并触发回调；未提供
  `onRetry` 时不出按钮；有计数时勾选仍回调 `onConfirmedChange(true)`。

## 非目标

- 不改变服务端 `previewDelete` 契约、计数口径或删除语义。
- 不自动重试（避免对降级实例连续打请求）；重试是显式操作。
- 不调整删除确认的 fail-open 行为。
- 不合并 UI-72（英文单复数）等其它 UI 发现。

## 验收标准

1. 影响面加载失败时，对话框内出现「重试」按钮；点击后重新进入加载态并发出一次新的预览请求。
2. 未传 `onRetry` 的调用方在失败态不出现按钮，行为与今天一致。
3. 加载态存在 `role="status"` 且其文本包含加载文案；该文案对明眼用户可见。
4. 影响面有计数时，删除按钮仍被禁用直到勾选确认；计数为 0 或读取失败时删除按钮可直接使用。
5. `vp check`、`vp run -r test`、`vp run -r build` 全绿。

## 架构边界

- 只改 `components/common` 的展示组件与其三个 feature 调用点，不新增依赖、不改 schema、
  不改投递/路由/auth 语义。
- `DeletionImpactNotice` 继续保持「纯展示、不读 query、不调 procedure」的边界：重试只是把
  回调交给 feature 自己的 `useDeletionImpact`。
- 文案复用现有 i18n key，不新增机器值翻译。
