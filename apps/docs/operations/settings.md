# 设置与运行态操作

「设置」是单实例 Tocsin 的运行控制面。它同时提供可写的实例偏好、真实的投递急停、账号会话处置、只读运行诊断，以及 TOML/JSON 配置导入导出。

该页面只对已登录的 dashboard 操作者开放。Webhook 使用告警源自己的 Token 或共享密钥，不能拿 dashboard session 代替。部署环境变量与数据库内设置也是两层不同配置，修改方式见[环境变量与运行时配置](/operations/configuration)。

## 先分清三层配置

| 层级 | 典型内容 | 修改后如何生效 | 是否进入可移植配置 |
| --- | --- | --- | --- |
| 进程环境 | 认证 URL/secret、数据库路径、出站超时、Webhook 上限、Worker 参数、日志级别与格式 | 重建容器或重启进程 | 否 |
| 数据库设置 | 语言、时区、原始载荷保留天数、出站投递暂停 | 保存后立即写入；部分偏好需刷新页面 | 前三项会进入；投递暂停不会 |
| 资源与历史 | 告警源、通知目标、路由、飞书应用、Event、Delivery、静默、用户与 session | 通过各自页面或数据库备份管理 | 仅配置类资源进入，历史和凭证不会 |

数据库设置可随数据库备份恢复。可移植配置适合复制和审阅配置，但不能替代[备份与恢复](/operations/backup-restore)。

## 页面结构

设置页包含三个页签：

| 页签 | 用途 |
| --- | --- |
| `UI` | 查看运行摘要；急停投递；查看账号会话；检查运行时、Worker 与 SQLite 存储；修改语言、时区和保留期 |
| `TOML` | 首选的可移植配置编辑、预览、导入和导出格式 |
| `JSON` | 与 TOML 使用同一文档模型和蛇形字段名的 JSON 形式 |

工具栏的「刷新」会重新获取设置页的只读投影，以及告警源、通知目标、路由等配置列表。它不是进程重启，也不会重新读取环境变量。

## 投递急停

「暂停出站投递」是实例级急停开关，勾选后立即生效，不经过偏好设置表单的保存按钮。

暂停期间：

- 投递 Worker 不领取新的投递任务，排队中的 Delivery 原样保留。
- 已有投递不会被标记为失败，也不会被删除；恢复后按退避时间和创建时间继续处理。
- 通知目标的「测试」动作绕过队列，仍会真实发送。
- 电话加急使用独立队列，不受这个开关直接暂停。若某条卡片投递被暂停，依赖它的自动加急也会推迟到投递恢复之后。

取消勾选会先打开确认框，提醒恢复积压可能再次向值班人员发送通知。恢复前先到[投递检索、生命周期与重试](/operations/deliveries)核对积压、目标可达性和暂停原因。

面板会显示当前暂停的开始时间与操作者。恢复后保留最近一次完整暂停区间，便于在变更或事故复盘中说明谁在何时停止了出站发送。暂停状态属于实例运行态，不进入 TOML/JSON 导出，也不应从一个环境复制到另一个环境。

## 账号安全

「账号安全」列出当前账号仍有效的 dashboard session，包括客户端、IP、最近活动、有效期和是否为当前会话。点击「退出其他设备」会撤销除当前浏览器之外的全部会话；当前会话保持不变。

这个动作只清理已签发的 session，不修改密码，也不等同于封禁账号。知道邮箱和密码的人之后仍可重新登录。账号恢复边界、认证密钥轮换和当前版本缺失的自助密码流程见[认证与账号安全](/operations/authentication)。

## 只读运行诊断

### 运行时与生效参数

「运行时与生效参数」从当前进程和实际运行配置读取，可用于核对当前部署是否与预期版本一致：

- Tocsin 版本、运行环境、Node 版本、平台与架构；
- 通知直链基址，即 `SERVER_URL` 或回落后的 `BETTER_AUTH_URL`；
- SQLite 驱动和活动连接报告的实际版本；
- 出站 HTTP 超时、Webhook 请求体上限；
- 投递与加急 Worker 共用的间隔、批量和超时回收窗口；
- 日志格式与级别。

通知直链基址为空或仍指向 `localhost` 时，面板会提示 `tocsin.eventUrl` 可能无法被收件人打开。修正 `SERVER_URL` 后重建容器，再核对事实行与提示是否消失。

该面板不会显示认证 secret、告警源 Token、目标凭证、数据库绝对路径或环境变量原文。若这里仍显示旧值，先确认容器是否已重建；只重启进程不会应用 Compose 中的新环境映射。

### 后台工作进程

「后台工作进程」并排显示投递 Worker 与加急 Worker 的进程内状态：

| 状态 | 含义 |
| --- | --- |
| `未启动` | 当前进程没有该 runner，先检查 readiness 与启动日志 |
| `空闲` | runner 已启动，当前没有正在执行的一批任务 |
| `运行中` | 正在处理一批任务 |
| `失败` | 上一批出现基础设施错误，需要查看最后错误 |

每列还显示上次开始/完成时间，以及上一批的领取、回收、成功、失败和重试数量。这个投影是当前进程的快照，不是历史指标；容器重启后会清空。队列积压与健康含义见[日志与可观测性](/operations/observability)和[生产监控与告警基线](/operations/monitoring)。

### 数据库存储

「数据库存储」显示 SQLite 主数据库体积、可回收空间、Event/Delivery/尝试/加急行数，以及最老与最新 Event 时间。

「可回收空间」来自 SQLite freelist，不等于宿主机磁盘余量，也不统计 `-wal`、`-shm`、日志和备份文件。保留策略、容量判断与安全处置顺序见[数据保留与 SQLite 容量](/operations/data-retention)。

## 偏好设置

「偏好设置」表单包含语言、IANA 时区和原始载荷保留天数。保存成功后，页面会重新加载以应用语言与时区；保留天数范围是 `0` 到 `3650`。

- 语言和时区用于 console 显示以及标准告警通知模板。
- 原始载荷保留天数只影响 Event 的原始 payload 和请求头。`0` 不是“关闭清理”，而是让后台清理尽快替换已超期的原始数据。
- 标准化字段、路由匹配快照、Delivery 和已渲染 payload 不会被这个保留期删除。

这些偏好与投递暂停分开保存。修改偏好不会意外恢复或暂停投递；恢复投递也不会覆盖另一标签页中刚修改的保留期。

## 可移植配置

首次打开 TOML 或 JSON 页签时，页面会把当前配置载入编辑器。点击「从文件载入」只替换编辑器文本，仍需点击「应用导入」并确认才会写入。

导入前预览会按资源 ID 汇总新增、更新和未变化项，并明确列出文件中没有出现、导入后仍会保留的现有配置。编辑器内容无法解析时，确认按钮会被禁用。

导入语义是合并，不是清空后重建：

- 文件中列出的告警源、通知目标、路由和飞书应用会新增或更新；
- 文件未列出的现有配置保持不变；
- 基础设置中的语言、时区和原始载荷保留期会按文件更新；
- Event、Delivery、静默、dashboard 用户、session、Source Token 和投递暂停状态不会出现在文件中；
- 导入结果中生成的 Source Token 只会显示一次，应立即保存到受保护的位置。

完整字段、密钥引用、导入事务和常见错误见[可移植配置参考](/operations/portable-config)。

## 值班操作顺序

### 需要立即停止外发通知

1. 在「设置 → UI」勾选「暂停出站投递」，确认面板显示开始时间与操作者。
2. 到投递页记录积压数量与最早等待时间；不要在暂停期间反复手动运行 Worker。
3. 修复目标、模板、上游风暴或网络问题，并用目标测试验证实际接收端。
4. 取消暂停，在确认框中核对影响，再持续观察 Worker 状态和新增 Delivery。
5. 确认积压已被领取并进入终态；如果恢复后再次失败，重新暂停，不要删除队列或数据库。

### 需要让其他设备立即下线

1. 在「设置 → UI → 账号安全」核对无法解释的 session。
2. 执行「退出其他设备」，并保持当前受控会话登录。
3. 检查告警源、通知目标、路由、飞书应用和设置是否出现未授权修改。
4. 若怀疑密码或认证材料泄露，限制 dashboard 外网访问并按账号恢复流程处置；只撤销 session 不足以恢复被泄露的密码。

### 需要核对部署是否生效

1. 在「运行时与生效参数」确认版本、SQLite 版本、通知直链基址、超时、Webhook 上限与 Worker 参数。
2. 在「后台工作进程」确认两个 runner 不是 `未启动` 或 `失败`。
3. 在「数据库存储」记录容量与行数基线。
4. 再发送一条代表性 Webhook，验证 Event、Route 和 Delivery，不能只看面板状态。

## 常见误区

| 现象 | 边界 |
| --- | --- |
| 修改 Compose 后设置页仍显示旧运行时值 | 需要 `docker compose up -d` 重建容器；刷新页面不能重读部署环境 |
| 收件人打不开通知里的事件链接 | 在运行时面板检查通知直链基址；本机地址或「未配置」都会产生不可用直链，修正 `SERVER_URL` 后重建容器 |
| 暂停投递后测试目标仍收到消息 | 测试动作绕过投递队列，是真实网络请求 |
| 恢复投递后立即出现一批通知 | 暂停期间积压被保留，恢复后 Worker 会继续领取 |
| 导入文件后旧配置仍在 | 导入按 ID 合并，未列出的现有配置不会删除 |
| 导出的 TOML 不能完整恢复实例 | 可移植配置不含历史、用户、session、Token 和运行态；完整恢复使用数据库备份 |
| 保留期设为 `0` 后没有立刻缩库 | 清理发生在后续 Webhook 或后台 sweep 时，SQLite 只释放页，不会自动缩小文件 |
| 「可回收空间」很大但宿主机仍满 | 该值不是磁盘剩余空间，也不包含 WAL、日志和备份 |
| Worker 显示 `空闲` 就说明告警已送达 | 空闲只说明 runner 当前没有执行批次，送达结果必须看 Delivery 终态 |
